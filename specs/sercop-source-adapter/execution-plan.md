## Binding constraints
- **Public names and signatures.** Fixed because the tests, the executor and F4 depend on them (source: intent AC1 to AC12, AC15). Every annotation is required; `domain` is checked by strict `mypy`.
  - `ec_procurement_quality.domain.source_response`:
    - `RawResponse`: an immutable record, built with keyword arguments and equal by value, with exactly the attributes `method: str`, `url: str`, `status: int`, `headers: tuple[tuple[str, str], ...]`, `captured_at: datetime.datetime` and `content: bytes`. These names are the `RawEvidenceStore.store` keyword names (RE-12), so F4 can pass the fields unchanged. Construction raises `ValueError` when `method` or `url` is empty, `status` is not an `int` from 100 to 599 (a `bool` is rejected), `headers` is not a tuple of `(str, str)` tuples, or `captured_at` has no UTC offset. It raises `TypeError` when `content` is not `bytes`. `Set-Cookie` is allowed here; the store drops it (RE-6). `repr()` and `str()` show neither the content nor any header value. Revision 2: the status range stays 100 to 599, equal to F1's `Observation` (RE-11), so every `RawResponse` the adapter builds can be stored; the adapter never builds one for a status outside that range (see § Outcome mapping).
    - `SourceError(Exception)`: the base class, built as `SourceError(message: str, *, response: RawResponse | None = None)`, with attribute `response: RawResponse | None`.
    - `SourceTransportError(SourceError)`: no complete, valid response was obtained. `response` is `None` when the failure came before the status and headers arrived, or (Revision 2) when the status received is outside 100 to 599. Otherwise it is the partial response: status, headers, the bytes received so far, and the capture time.
    - `SourceStatusError(SourceError)`, built with a required keyword `response: RawResponse`: a complete response whose status is not `200`.
    - `IncompleteResponseError(SourceError)`, built with a required keyword `response: RawResponse`: a complete `200` whose body fails the completeness checks.
    - This set is closed (intent AC15, Revision 2). A call returns a result or raises one of these four errors, `ValueError` for invalid input or construction, or `RuntimeError` for a call after `close()`. No `httpx` exception and no untyped `ValueError` leaves a call for anything the source sends. Every other exception propagates unchanged and is never wrapped: `KeyboardInterrupt`, `SystemExit`, and any exception that is not an `httpx.HTTPError` and comes from an injected transport or from `now`, `monotonic` or `sleep`. Why the set holds is shown in § Closed-set justification below.
  - `ec_procurement_quality.application.procurement_source`:
    - `SearchPage`: immutable, with exactly `response: RawResponse`, `total: int`, `page: int`, `pages: int` and `record_count: int` (the length of `data`), and the read-only property `is_beyond_last_page: bool`, true exactly when `page > pages`.
    - `RecordResponse`: immutable, with exactly `response: RawResponse`, `ocid: str` and `release_count: int`.
    - `ProcurementSource`: a `typing.Protocol` (it need not be `runtime_checkable`) with exactly these methods:
      ```python
      def search_page(self, *, year: int, buyer: str, page: int) -> SearchPage: ...


      def fetch_record(self, ocid: str) -> RecordResponse: ...
      ```
      Both raise the `SourceError` subclasses above, and `ValueError` for invalid input.
  - `ec_procurement_quality.infrastructure.sercop_source`:
    - `DEFAULT_BASE_URL = "https://datosabiertos.compraspublicas.gob.ec/PLATAFORMA"` (Obs. § Confirmed search endpoint, § Record endpoint and rate limiting).
    - `SercopSource`, built only with keyword arguments: `base_url: str = DEFAULT_BASE_URL`, `transport: httpx.BaseTransport | None = None` (`None` means the library's real transport), `connect_timeout: float = 10.0`, `read_timeout: float = 30.0`, `min_interval: float = 5.0`, `low_remaining_threshold: int = 20`, `cooldown: float = 60.0`, `now: Callable[[], datetime] = <the current local time with its UTC offset>`, `monotonic: Callable[[], float] = time.monotonic`, `sleep: Callable[[float], None] = time.sleep`.
    - It satisfies `ProcurementSource` structurally; subclassing is allowed but not required. It owns one `httpx.Client`, has `close()`, and works as a context manager (`__enter__` returns itself, `__exit__` closes it). `close()` may be called more than once. Revision 2: a call after `close()` raises `RuntimeError` before any request and before any wait, and changes no pacing state (intent AC10).
    - Construction raises `ValueError` when `base_url` is not an absolute `http` or `https` URL, or ends with `/`, or has a query or fragment. It also raises `ValueError` when a timeout is not positive, when `min_interval` or `cooldown` is negative, or when `low_remaining_threshold` is not a non-negative `int` (a `bool` is rejected).
    - Revision 2, the authority of `base_url` (source: intent AC10; `AGENTS.md`; ADR 0003; the probes in § Guidance consulted). Construction also raises `ValueError` when:
      - the authority holds user information: any `@` in it, even with nothing before it (`https://@host/...`). This check runs before any parsing whose message could repeat the URL;
      - the host is empty (`https://:8443/PLATAFORMA`);
      - a `:` follows the host (outside the brackets of an IPv6 literal) and what follows it is not 1 to 5 ASCII digits (`0`-`9` only) with a value from 1 to 65535. So `:`, `:abc`, `:+8443`, `:-1`, `:٣`, `:0`, `:65536` and `:99999` are rejected; `:1`, `:8443` and `:65535` are accepted. The library accepts several of the rejected forms and reads `٣` as 3; and on Windows `getaddrinfo` wraps 99999 to 34463, while `socket.connect` raises an unmapped `OverflowError`;
      - `httpx.URL(base_url)` raises `httpx.InvalidURL` (for example `https://999.1.1.1/PLATAFORMA`, an invalid IDNA host, or a control character such as a newline, which `urlsplit` would silently remove). `InvalidURL` itself never leaves the constructor.
      - The `ValueError` message names `base_url` and a fixed reason. Its message, `__cause__` and `__context__` never contain the given URL or any part of its user information: raise it outside the `except` block that caught `InvalidURL`, whose text can repeat parts of the URL, the same pattern § No content in errors requires for JSON errors.
- **Request format** (source: Obs. § Confirmed search endpoint, § Record endpoint and rate limiting, § Minimum pending checks; Series § `local=1`):
  - Search: `GET {base_url}/api/search_ocds?local=1&year={year}&page={page}&buyer={quote(buyer, safe="")}`, with `year` and `page` as plain decimal numbers. The parameters come in this order, and there is no other parameter. `local=1` is a constant with no meaning in code; it is sent because the confirmed query has it. The URL is built as a string and sent unchanged, not through `params=`, because `params=` writes spaces as `+` (checked above) and the observed query uses `%20`.
  - Record: `GET {base_url}/api/record?ocid={quote(ocid, safe="")}`.
  - `RawResponse.url` is `str(request.url)` of the request actually sent; for the two forms above it equals the built string. `RawResponse.method` is `GET`.
  - Every request carries `Accept-Encoding: identity` and never a `Cookie` header, even after a response that set one (**project decision**: the observation requests were made with `curl`, which sent neither). Other request headers are the library defaults. They are not recorded (ADR 0005) and are not a contract.
  - Exactly one request per call. Redirects are not followed, and a `3xx` is a status error. Revision 2: the `Location` header is kept as received and never decides the outcome. `httpx.Client` builds a redirect request for every `301`, `302`, `303`, `307` and `308` that has a `Location` header, even with `follow_redirects=False` (`_send_handling_redirects` calls `_build_redirect_request` before it checks the flag), and that step raises `httpx.RemoteProtocolError` or `httpx.InvalidURL` for some values, closing the response first (probe in § Guidance consulted). The adapter must have captured the status, the headers and the body (or its partial bytes) before that step runs, and an exception the library raises in that step must not change the outcome decided from the capture (suggested mechanism in § Proposed approach).
  - Timeouts: `connect` = `write` = `pool` = `connect_timeout`, and `read` = `read_timeout`. The defaults are 10 s and 30 s (**project decision, not observed**). The read default is above the longest whole request observed (12.01 s, Series table) and well above the `httpx` default of 5 s. No overall deadline per request exists (see § Risks).
  - Input validation, before any request and before any wait. It raises `ValueError` when `year` is not an `int` or is a `bool` or is below 1, when `page` is not an `int` or is a `bool` or is below 1, or when `buyer` or `ocid` is not a non-empty `str`. Nothing else is assumed about valid years, pages, buyer names or `ocid` formats. A failed validation changes no pacing state.
  - Revision 2, order of a call (source: intent AC10, AC15): (1) the closed check (`RuntimeError`); (2) the argument checks above; (3) building the request with `Client.build_request`; (4) the pacing wait; (5) sending. A request URL that the library rejects in step 3 raises `ValueError` (fixed message naming the operation, no URL text, raised outside the `except` block), with no wait, no request and no change to pacing. With `base_url` checked at construction, the only cause left is a URL longer than `MAX_URL_LENGTH` (65,536 characters in `httpx` 0.28.1), reached by a long buyer name or `ocid`. Tests use 70,000 characters so that they do not depend on the exact limit.
- **Response capture** (source: ADR 0005 "as received"; Series § Response body: chunked, no `Content-Length`; Series § Other response behavior: repeated header names):
  - The response is streamed. `RawResponse.content` is the concatenation of the raw body chunks, after chunked transfer decoding and before any content decoding (`iter_raw`). The body is read completely before the outcome is decided.
  - `RawResponse.headers` are the response headers in order, with names in the case received and repeats kept, each name and value decoded from bytes as Latin-1 (**project decision**: lossless for any byte, and plain ASCII is unchanged). `Set-Cookie` is kept.
  - `now()` is called once per response received, when the body has been read completely or its reading has failed. The value becomes `captured_at`. For a status outside 100 to 599 no `RawResponse` is built, and calling `now()` is neither required nor forbidden.
- **Outcome mapping**, a closed list in this order (source: intent AC5 to AC7, AC15; Revision 2 adds rule 2 and the last two paragraphs):
  1. An `httpx.HTTPError` while sending or before the status arrives raises `SourceTransportError` with `response=None`.
  2. A status outside 100 to 599 raises `SourceTransportError` with `response=None`, whatever the body and whether or not its reading failed. The message names the operation, the status number and a fixed reason (for example `search_ocds: the source answered an invalid HTTP status 600`). No `RawResponse` is built for it, so the `ValueError` of its validation can never escape.
  3. An `httpx.HTTPError` while reading the body raises `SourceTransportError` with the partial response.
  4. A status other than `200` raises `SourceStatusError` with the complete response. Only `200` was ever observed as success, so `204`, `206` and `3xx` are status errors too, whatever the `Location` header holds.
  5. A `200` that fails a completeness check raises `IncompleteResponseError` with the complete response.
  6. Otherwise the call returns `SearchPage` or `RecordResponse`.

  The outcome is decided from what was captured. Once the status and headers have been captured, an `httpx.HTTPError` or `httpx.InvalidURL` raised by the library's redirect step (above) is ignored: it is neither raised nor chained as `__cause__` or `__context__`, because its message can repeat the `Location` value, which is a header value (AC8). Raise the mapped error outside the `except` block.

  Anything else is not mapped and propagates unchanged (see the closed set above).
- **Completeness checks** (source: Series § Response body, § Pagination, § `api/record`; ADR 0005 consequences). The body is decoded with `bytes.decode("utf-8")` (strict, so a BOM or any invalid byte fails) and parsed with `json.loads`. Integers below are JSON integers: a Python `int` that is not a `bool`.
  - Search: the top level is an object; `total`, `page` and `pages` are non-negative integers; `data` is a list; and `page` equals the requested page (**project decision**, built on "`page` echoed the requested number" in Series § Pagination). `record_count` is `len(data)`.
  - Record: the top level is an object; `releases` is a non-empty list; every release is an object whose `ocid` is a string equal to the requested `ocid`. Only one release was observed, so requiring every release to match when there are more is a **project decision**. `release_count` is `len(releases)`.
  - Nothing else is checked: not the record keys or their types, not page sizes, not `total` against `pages`, not `Content-Type` and not other OCDS sections. An in-range page with an empty `data` is valid, because no rule was observed for it.
- **Pacing** (source: Series § Rate limiting; Obs. § Record endpoint and rate limiting, "pace requests conservatively and handle `429` with backoff"). State per adapter instance, in memory only:
  - After every attempt that reached the transport, the adapter records `monotonic()` when the attempt ended (body read, read failed, or send failed). It sets "cool-down required" exactly when the attempt received a response, complete or partial, that has status `429` or whose lowest valid `X-RateLimit-Remaining` value is below `low_remaining_threshold`. The header name is matched ignoring case. A valid value is ASCII decimal digits after stripping surrounding whitespace; any other value is ignored.
  - Revision 2 (source: intent AC9, AC15). An attempt starts when the request is handed to `Client.send`, after the checks of § Request format and after the wait. From then on, the end time is recorded on every exit path before the call returns or raises: a result, a `SourceError`, and also an exception that propagates unchanged, `KeyboardInterrupt` and `SystemExit` included (for example with `try`/`finally`). "Cool-down required" is decided from the status and headers whenever they arrived, whether the body was read completely, read partly or interrupted, and whatever the status, one outside 100 to 599 included; it is cleared when no status and headers arrived. Before an attempt starts (closed adapter, invalid input, URL rejected in step 3, an exception from `sleep`), the pacing state does not change. In the code built for Revision 1, an exception that escapes `_send` skips the update of `_last_attempt_end`, so the next call does not wait at all, even after a `429` whose body read was interrupted; this rule closes that gap.
- **Closed-set justification** (Revision 2; source: intent AC15; the `httpx` 0.28.1 sources and probes in § Guidance consulted). The calls that can raise are `Client.build_request`, `Client.send(request, stream=True)`, `Response.iter_raw()` and `Response.close()`. Every type in `httpx/_exceptions.py` is covered below, so the closed set rests on this reasoning, not on an assumption. The auditor checks each line against the installed package.
  - `httpx.HTTPError` and all its subclasses: mapped by rules 1, 3 and 4 of § Outcome mapping. Those raised by the redirect step after the capture are ignored. `DecodingError` (raised only by content decoding, which `iter_raw` skips), `TooManyRedirects` (redirects are not followed) and `HTTPStatusError` (raised only by `raise_for_status`, which is not called) cannot be raised on this path; if one were, it would still be mapped.
  - `httpx.InvalidURL` can come from three places, each closed: (a) `base_url`, now checked at construction, including by `httpx.URL` itself; (b) the request URL in `build_request`. The adapter appends only `/api/search_ocds` or `/api/record`, `?`, `&`, `=`, ASCII decimal digits and `quote(..., safe="")` output (unreserved ASCII and `%XX`) to a base URL that was already accepted and has no query, fragment or trailing `/`. So no control character, host, port or path rule can fail, and the only cause left is `MAX_URL_LENGTH`, which becomes `ValueError` before the wait (§ Request format); (c) the redirect step in `send` (`URL(location)`, `URL.join`, `URL.copy_with`), ignored after the capture. After these changes it cannot leave a call.
  - `httpx.CookieConflict` is raised only by `Cookies.get()`. Neither the adapter nor the send path calls it: `extract_cookies` goes through `http.cookiejar`, which catches its own parse errors. Unreachable.
  - `httpx.StreamConsumed` and `httpx.StreamClosed` are raised by `Response.iter_raw()` only when the stream was already read or closed, or is an `UnattachedStream` (unpickled). The library's transport returns a fresh `ResponseStream`, and the adapter reads each response once and closes it only after reading. They are unreachable with `transport=None`. They can occur only with an injected transport that returns a response already read or closed, such as a `MockTransport` response built with `content=`. That is a test-double defect, and it propagates unchanged.
  - `httpx.ResponseNotRead` is raised by `Response.content`, `.text` and `.json()` before a read, and `httpx.RequestNotRead` by `Request.content` on a streamed request body. The adapter uses none of these, and a `GET` has no body. Unreachable.
  - `RuntimeError` from the client: "client has been closed" is pre-empted by the closed check (step 1), so the adapter raises it before any wait. "Async request with a sync client", "sync iterator on an async stream" and the `AssertionError` on a non-sync stream need an injected transport that returns async streams. That is a test-double defect, and it propagates unchanged.
  - Below `httpx`: `HTTPTransport` wraps request handling and body iteration in `map_httpcore_exceptions`, which maps `httpcore`'s hierarchy, and `httpcore`'s sync backend maps `OSError` and `socket.timeout`. The one unmapped path found, `OverflowError` from `socket.connect` for a port above 65535, is closed by the port rule at construction. Any other exception from this level would be a library defect, not a source outcome. Like any exception from an injected transport or callable, it propagates unchanged and still counts for pacing.
  - Before each request after the first, the required gap is `cooldown` if cool-down is required and `min_interval` otherwise. The wait is that gap minus the time elapsed since the previous attempt ended. If the wait is positive, `sleep(wait)` is called exactly once; otherwise it is not called. The first request of an instance never waits.
  - `X-RateLimit-Limit`, `Retry-After` and reset headers are not read. The meaning of `Remaining` is taken only as observed: a counter that falls, is present on every `200`, and is not a function of this client's own request count. Nothing is assumed about the window or the key.
  - Defaults are **project decisions, not observed**: `min_interval` 5 s (the series spaced requests 4 to 14 s apart and saw no `429`), `low_remaining_threshold` 20 (the stop rule the human used in the series), `cooldown` 60 s (the series only showed a refill within 29 minutes; "about a minute" is an inference there, not a measurement).
- **No content in errors, representations or logs** (source: `AGENTS.md`; RE-7, `raw-evidence` Invariant 5 and reservation N3):
  - Messages name the operation (`search_ocds` or `record`), the status when there is one, and a fixed reason. They never contain body bytes or header values.
  - No `__cause__` or `__context__` in the chain of a raised error is a `json.JSONDecodeError` or `UnicodeDecodeError`, both of which keep the body: raise the incomplete-response error outside the `except` block. An `httpx` exception may be chained as `__cause__` of a `SourceTransportError`. It holds no body; callers must not catch it by type.
  - The adapter creates no logger and writes nothing to stdout or stderr. The `httpx` `INFO` record (URL and status) is library behavior and is not suppressed.
- **Layer imports** (source: `AGENTS.md`; PT-3; ADR 0006): `domain` imports only the standard library and itself; `application` only the standard library, `domain` and itself; `infrastructure` may import `domain`, `application` and `httpx`; no module outside `infrastructure` imports `httpx`. Nothing in F2 imports `interfaces`.
- **Dependency** (source: the human's approval; ADR 0006; PT-11; ADR 0004): O1 runs `uv add httpx`. It adds one entry to `[project] dependencies` with the lower bound `uv` writes for the resolved version, and updates `uv.lock`. The `dev` group and the build system do not change, and no other direct dependency is added.
- **F1 is consumed, not changed**: `domain/content_hash.py`, `domain/raw_evidence.py`, `application/raw_evidence_store.py` and `infrastructure/local_disk_raw_evidence_store.py` do not change (source: intent § Constraints, ADR 0005).
- **Package root**: no new file directly in `src/ec_procurement_quality/` (source: `project-toolchain` Invariant 3).
- **Tests stay offline and synthetic** (source: intent AC11; `AGENTS.md`; fixtures README):
  - Every adapter test injects an `httpx.MockTransport`, and a network guard is active in them (§ Proposed approach).
  - Fixtures are read from `tests/fixtures/sercop/` and never written. Truncated, `429`, `5xx` and other bodies are built in test code, with names or comments that say they are synthetic.
  - URLs use `https://source.invalid/PLATAFORMA`. No test file contains the real host.

## Proposed approach
Revisable by the executor if it records why.
- Decision: **the adapter makes a single attempt; retries and backoff belong to the caller (F4, `application`)**. Rationale:
  - Every response reaches the caller, and so the store, as soon as it is received, before any wait (ADR 0005, glossary "observation": one per response obtained). If F4 stores after every call, a crash or `Ctrl+C` during a backoff loses nothing.
  - One call is one request is one outcome, which matches F1's one observation per response and lets F4 assign one sequence per response.
  - How many times to retry is policy of a bounded, resumable ingestion execution (attempt budget, audit, resume point), which F4 owns anyway.
  - The decision needs only `domain` types (`SourceStatusError.response.status`, `SourceTransportError`), so `application` never sees `httpx`.
  - F2 still protects the source from a naive caller: after a `429` or a low `Remaining`, the next request waits the cool-down, whatever F4 does.
  - Rejected: an adapter that retries and returns every attempt. It would hold the earlier responses in memory through sleeps, so they are lost on a crash or interruption unless every exit path, `KeyboardInterrupt` included, hands them back. It would need a list-of-attempts result and error type, and F4 would still need its own retry state to resume. Rejected also: letting the library retry (`HTTPTransport(retries=...)`), because those attempts would never reach the store (ADR 0006).
- Decision: **return the response as received in a `domain` value whose attribute names equal the `store` keywords**. Rationale: F4 calls `store(execution_id=..., sequence=..., method=r.method, url=r.url, status=r.status, headers=r.headers, captured_at=r.captured_at, content=r.content)` with no translation, and F1 does not change. Rejected: returning an `httpx.Response` (it leaks `httpx` out of `infrastructure`, ADR 0006), or an `Observation`-like record that holds a hash (hashing is the store's job, RE-1 and RE-2).
- Decision: **every error carries the response it saw, through one attribute on the base class** (`SourceError.response`). Rationale: F4 needs one rule (`except SourceError as error: if error.response is not None: store it`), and "never partial data" holds because no result object exists on any error path. Rejected: a result union with an "ok" flag, because a caller could ignore the flag and use partial data.
- Decision: **stream the body with `iter_raw` and ask for `Accept-Encoding: identity`**. Rationale: `iter_raw` gives the exact received bytes and keeps the bytes already read when the body is cut off (checked above), so a truncated body is still evidence. Asking for identity makes compression unlikely, and if the server compresses anyway, the bytes stay raw and the body fails the JSON check instead of being silently decoded. Rejected: `response.content`, because it applies content decoding and loses the partial bytes on a cut.
- Decision: **build the query string with `urllib.parse.quote(value, safe="")`**, so the request equals the observed URL byte for byte. Rejected: `params=`, which writes spaces as `+` (checked above). Whether the server treats `+` the same way is unknown, so it is not assumed.
- Decision: **no cookie is ever sent** (suggestion: give the client a cookie jar whose policy accepts nothing, such as `http.cookiejar.CookieJar(policy=http.cookiejar.DefaultCookiePolicy(allowed_domains=[]))`, or clear `client.cookies` before each request; confirm in `.venv`). Rationale: requests must not depend on earlier responses in ways the observations never showed; the AC3 test is the requirement.
- Decision: **completeness checks are pure functions of the body bytes and of the requested page or `ocid`** (suggestion). Rationale: F5 or an audit tool can run the same checks again on stored evidence (see § Consumers and migration).
- Decision: **network guard**. The suggested design is an `autouse` pytest fixture, in `tests/unit/test_sercop_source.py` or a new `tests/unit/conftest.py`; either works.
  - The fixture replaces `socket.socket.connect`, `socket.socket.connect_ex`, `socket.create_connection` and `socket.getaddrinfo` through `monkeypatch`. Each replacement records the attempt and raises `OSError`.
  - At teardown, the fixture fails the test if anything was recorded, so a real connection fails the test even if the adapter turned the `OSError` into a `SourceTransportError`.
  - The `no_network` proof test opts out of that teardown assertion, builds `SercopSource(base_url="https://source.invalid/PLATAFORMA")` with no transport, calls it, and asserts that at least one attempt was recorded and that `SourceTransportError` was raised.
  - The reserved `.invalid` domain (RFC 6761) never resolves, which gives a second line of defense.
  - Rejected: an extra package such as `pytest-socket` (no new dependency), or relying on `.invalid` alone (a missing transport would still try DNS).
- Decision: **simulated transport responses** (test-writer note, from the check above):
  - Build mock responses with `httpx.Response(status, headers=[...], stream=httpx.ByteStream(body))`, or with a small `httpx.SyncByteStream` subclass that yields chunks and can raise `httpx.RemoteProtocolError` or `httpx.ReadTimeout` partway.
  - `content=` adds `Content-Length` and is read eagerly, so the adapter's `iter_raw` would raise `StreamConsumed`. Tests that compare exact header lists must not use it.
  - A handler that raises `httpx.ConnectError` or `httpx.ReadTimeout` (with `request=request`) simulates a failure before the status.
  - The handler records every request so a test can assert the URL, the headers, `request.extensions["timeout"]` and the number of requests.
- Decision: **fake clocks**. A fake `monotonic` returns a value the test controls, and a fake `sleep` records each duration and advances that value. The test sets the time between calls by moving the fake clock forward. `now` returns a fixed aware datetime such as `2026-10-10T06:58:00-05:00`. Test values are whole seconds, so the waits compare exactly.
- Revision 2 decisions (suggestions; the tests are the requirement):
  - Decision: **capture each response in an `httpx` response event hook** (`httpx.Client(event_hooks={"response": [...]})`). The client calls the hook right after the transport answers and before its redirect step (`_send_handling_redirects`). The hook reads the body with `iter_raw`, keeps the bytes read so far on an `httpx.HTTPError`, and stores the status, raw headers, bytes and failure on the adapter. It builds no `RawResponse`, because a status outside 100 to 599 would make that raise inside the client. After `send` returns, or raises from its redirect step, the adapter decides the outcome from that capture. Rationale: it stays within `httpx.Client` (ADR 0006), keeps streaming and partial bytes, and makes the `Location` header irrelevant to the outcome. Rejected: catching the redirect-step error after `send`, because the client has already closed the response and the body is lost. Rejected: calling `transport.handle_request` directly, because it bypasses `httpx.Client`, against the wording of ADR 0006, and changes how environment proxies are applied.
  - Decision: **build the request before the pacing wait**, and turn `httpx.InvalidURL` from `build_request` into `ValueError`. Rationale: invalid input never waits (AC10). Rejected: a hand-written length limit, because it would duplicate the library's rule and could drift from it.
  - Decision: **check `base_url` with explicit rules plus `httpx.URL(base_url)`** at construction. The explicit rules cover user information, the empty host and the port, which the library accepts in forms that are wrong for this project. The library parse covers every other form it would reject later. Rejected: the library parse alone, because it accepts `https://:443/...`, user information and out-of-range ports.
  - Decision: **record the end of the attempt in a `finally`** that starts when the request is handed to `send`. The cool-down flag is taken from the captured status and headers, if any.
  - Decision: **a closed flag checked first in each call**, raising `RuntimeError`, the type the library itself uses for a closed client. Rejected: `ValueError`, because the arguments are valid.
- Suggested test files and names (the `-k` tokens are used by the commands in § Validation, so test names must contain them):
  - `tests/unit/test_source_response.py` for `RawResponse` and the errors: `invalid` (AC10 domain part), `no_leak` (AC8 `repr` and `str`).
  - `tests/unit/test_sercop_source.py` for the adapter: `search_success` and `query` (AC1), `record_success` (AC2), `raw_response`, `store_shape` and `cookie` (AC3), `out_of_range` and `no_results` (AC4), `status_error` (AC5), `transport` (AC6), `incomplete` (AC7), `no_leak` (AC8), `pacing` (AC9), `timeout`, `accept_encoding` and `invalid` (AC10), `no_network` (AC11), `satisfies_port` (AC12).
  - Revision 2, in `tests/unit/test_sercop_source.py` (exact names and cases in `tasks.md` O2b): new cases in `STATUS_CASES` (`status_error`, AC5); `test_transport_invalid_status_is_a_transport_error_without_response` (`transport`, AC6); new `PACING_CASES` and `test_pacing_counts_an_attempt_that_ends_in_an_unmapped_exception` (`pacing`, AC9); new cases in `test_invalid_construction_options_raise_value_error`, plus `test_invalid_base_url_with_userinfo_is_rejected_without_echoing_it`, `test_invalid_input_too_long_for_a_url_raises_value_error_before_any_request_or_wait` and `test_invalid_use_after_close_raises_runtime_error_before_any_wait` (`invalid`, AC10); `test_transport_defect_from_an_injected_transport_propagates_unchanged` (`transport` and `transport_defect`, AC15). `tests/unit/test_source_response.py` and `tests/unit/test_layers.py` do not change.
  - `tests/unit/test_layers.py`: add `test_layer_only_infrastructure_imports_httpx`, reusing `_imported_modules`. Like the F1 port check, it must not pass vacuously: it asserts that `infrastructure/sercop_source.py` exists and imports `httpx`, then that no module under `domain`, `application` or `interfaces` (or directly in the root package) imports `httpx` in any form.
