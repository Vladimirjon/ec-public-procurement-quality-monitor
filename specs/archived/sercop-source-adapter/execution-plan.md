## Binding constraints
- **Reading rule (Revision 5, audit F-8).** This plan says in several places that an exception the adapter raises has no `__cause__` or `__context__`, that nothing is chained, or that its chain holds no exception of some kind. Each of those places means § Output invariant I2: no cause, and a context that is only the exception the caller was already handling, left visible. So nothing raised during the call is reachable through the chain.
- **Public names and signatures.** Fixed because the tests, the executor and F4 depend on them (source: intent AC1 to AC12, AC15). Every annotation is required; `domain` is checked by strict `mypy`.
  - `ec_procurement_quality.domain.source_response`:
    - `RawResponse`: an immutable record, built with keyword arguments and equal by value, with exactly the attributes `method: str`, `url: str`, `status: int`, `headers: tuple[tuple[str, str], ...]`, `captured_at: datetime.datetime` and `content: bytes`. These names are the `RawEvidenceStore.store` keyword names (RE-12), so F4 can pass the fields unchanged. Construction raises `ValueError` when `method` or `url` is empty, `status` is not an `int` from 100 to 599 (a `bool` is rejected), `headers` is not a tuple of `(str, str)` tuples, or `captured_at` has no UTC offset. It raises `TypeError` when `content` is not `bytes`. `Set-Cookie` is allowed here; the store drops it (RE-6). `repr()` and `str()` show neither the content nor any header value. Revision 2: the status range stays 100 to 599, equal to F1's `Observation` (RE-11), so every `RawResponse` the adapter builds can be stored; the adapter never builds one for a status outside that range (see § Outcome mapping).
    - `SourceError(Exception)`: the base class, built as `SourceError(message: str, *, response: RawResponse | None = None)`, with attribute `response: RawResponse | None`.
    - `SourceTransportError(SourceError)`: no complete, valid response was obtained. `response` is `None` when the failure came before the status and headers arrived, or (Revision 2) when the status received is outside 100 to 599. Otherwise it is the partial response: status, headers, the bytes received so far, and the capture time.
    - `SourceStatusError(SourceError)`, built with a required keyword `response: RawResponse`: a complete response whose status is not `200`.
    - `IncompleteResponseError(SourceError)`, built with a required keyword `response: RawResponse`: a complete `200` whose body fails the completeness checks.
    - This set is closed (intent AC15, Revision 2). A call returns a result or raises one of these four errors, `ValueError` for invalid input or construction, or `RuntimeError` for a call after `close()`. No `httpx` exception and no untyped `ValueError` leaves a call for anything the source sends. Every other exception propagates unchanged and is never wrapped: `KeyboardInterrupt`, `SystemExit`, and any exception that is not an `httpx.HTTPError` and comes from an injected transport or from `now`, `monotonic` or `sleep`. Revision 3: `MemoryError` also propagates unchanged (no body-size limit; intent AC15 and Open questions). Why the set holds is shown in § Closed-set justification and § Family check below. Revision 4 (intent AC8, AC15):
      - Every exception the adapter raises itself satisfies § Output invariant: its type is exactly one of the five types, nothing is chained, and its message is fixed text.
      - "Not an `httpx.HTTPError`" is the test for what propagates unchanged from an injected transport. `httpx.InvalidURL`, `httpx.CookieConflict` and the `httpx.StreamError` family are therefore test-double defects there.
      - With the default transport, an error that construction raises while reading the environment's proxy or certificate settings propagates unchanged.

- **Response capture** (source: ADR 0005 "as received"; Series § Response body: chunked, no `Content-Length`; Series § Other response behavior: repeated header names):
  - The response is streamed. `RawResponse.content` is the concatenation of the raw body chunks, after chunked transfer decoding and before any content decoding (`iter_raw`). The body is read completely before the outcome is decided.
  - `RawResponse.headers` are the response headers in order, with names in the case received and repeats kept, each name and value decoded from bytes as Latin-1 (**project decision**: lossless for any byte, and plain ASCII is unchanged). `Set-Cookie` is kept.
  - `now()` is called once per response received, when the body has been read completely or its reading has failed. The value becomes `captured_at`. For a status outside 100 to 599 no `RawResponse` is built, and calling `now()` is neither required nor forbidden.
- **Outcome mapping**, a closed list in this order (source: intent AC5 to AC7, AC15; Revision 2 adds rule 2 and the last two paragraphs):
  1. An `httpx.HTTPError` while sending or before the status arrives raises `SourceTransportError` with `response=None`.
  2. A status outside 100 to 599 raises `SourceTransportError` with `response=None`, whatever the body and whether or not its reading failed. The message names the operation, the status number and a fixed reason (for example `search_ocds: the source answered an invalid HTTP status 600`). No `RawResponse` is built for it, so the `ValueError` of its validation can never escape.
  3. An `httpx.HTTPError` while reading the body raises `SourceTransportError` with the partial response.
  4. A status other than `200` raises `SourceStatusError` with the complete response. Only `200` was ever observed as success, so `204`, `206` and `3xx` are status errors too, whatever the `Location` header holds.
  5. A `200` that fails a completeness check raises `IncompleteResponseError` with the complete response.
  6. Otherwise the call returns `SearchPage` or `RecordResponse`.

  The outcome is decided from what was captured. Once the status and headers have been captured, an `httpx.HTTPError` or `httpx.InvalidURL` raised by the library's redirect step (above) is ignored: it is neither raised nor chained as `__cause__` or `__context__`, because its message can repeat the `Location` value, which is a header value (AC8). Raise the mapped error outside the `except` block. Revision 3: the same holds for an exception of any type from that step (§ Request format); the suggested mechanism removes the step, so nothing is raised there to ignore.

  Anything else is not mapped and propagates unchanged (see the closed set above).

- **Pacing** (source: Series § Rate limiting; Obs. § Record endpoint and rate limiting, "pace requests conservatively and handle `429` with backoff"). State per adapter instance, in memory only:
  - After every attempt that reached the transport, the adapter records `monotonic()` when the attempt ended (body read, read failed, or send failed). ### Output invariant (Revision 4)
Source: intent AC8, AC10, AC15; audit F-5 and F-6. This is the property that the tests check structurally, whatever the input. It replaces checks that looked for one known input at a time. It applies to every exception the adapter raises itself: any instance of `SourceError`, and every `ValueError` or `RuntimeError` raised by the constructor or by a call. Exceptions that propagate unchanged (§ Exit check, outcome "pass-through") are not raised by the adapter and are outside it. Revision 5: "raises itself" means that the adapter creates the exception. An exception that caller code raises, or that is raised while a value returned by caller code is used, is outside the invariant even when its type is `ValueError` (§ Binding constraints, caller code). The rules below hold for every legal input and every test double, under the one-caller rule.

Revision 5 restates I2, I3 and I4 (audit F-8 and F-9; § Statement check). I1 is unchanged. Every existing test calls the adapter while handling no exception, so for those tests the new I2 says exactly what the old one said: no cause and no context. The new I4 reads the same text as the old one whenever the context is `None`. No existing assertion becomes inconsistent with these rules.

| # | Rule | Checked as |
|---|---|---|
| I1 | Type | `type(error)` is exactly one of `SourceTransportError`, `SourceStatusError`, `IncompleteResponseError`, `ValueError`, `RuntimeError`. A subclass of `ValueError` from the interpreter or a library (`UnicodeEncodeError`, `idna.IDNAError`, `httpx.InvalidURL`) fails it. |
| I2 | Nothing chained from the call (Revision 5) | `error.__cause__ is None`, `error.__suppress_context__ is False`, and `error.__context__ is C`. C is the value of `sys.exception()` when the call or the construction started: the exception that the caller was handling in an `except`, a `finally` or an `__exit__`, or `None`. So no exception raised during the call, by a library, the interpreter or the adapter's own checks, is reachable through `__cause__` or `__context__`. Revision 4 read "`error.__context__ is None`", which no code can meet for a call made inside the caller's handler (audit F-8). |
| I3 | Fixed text (Revision 5) | `error.args == (str(error),)`, and `str(error)` is printable ASCII (`str.isascii()` and `str.isprintable()`). It starts with one of `search_ocds: `, `record: `, `base_url `, `connect_timeout `, `read_timeout `, `min_interval `, `cooldown `, `low_remaining_threshold `, `transport `, `now `, `monotonic `, `sleep `, `year `, `page `, `buyer `, `ocid `, or it equals `the source adapter is closed`. Source errors name the operation; input and option errors name the parameter. There are only two variable parts. The first is the status, written as the decimal digits of an exact `int`. The second, in rules 1 and 3 of § Outcome mapping, is one name from the closed list there: the nearest class that `httpx` exports. Revision 4 copied `type(failure).__name__` and wrote the status through its own `__format__`, so a test double could make the text non-ASCII or put a marker in it (audit F-9; § Statement check). |
| I4 | No input text (Revision 5) | No marker placed in an input appears in `"".join(traceback.format_exception(error, chain=False))`, `repr(error)` or `repr(error.args)`. The inputs are: the base URL and the other options; the call's arguments; and what the transport delivers, namely the status, the header names and values, the body, and the class and text of an exception it raises. When the marker sits in what the transport delivers, it also must not appear in `repr(error.response)` or `str(error.response)`. When it sits in what the caller gave, the response's `url` holds it as sent, so the response is not checked. `chain=False` leaves out the context that I2 allows: that context is the caller's own exception, and it may hold anything. The traceback also quotes the source lines of the caller's own frames, and those lines are the caller's text. So the tests pass every marker through a variable, never as a literal in the line that makes the call. |

The sweep. Three test groups build their inputs as the product of finite lists that are pinned in § Validation (AC8 row), plus a fourth group of named cases. They assert I1 to I4 on every case. The lists put a marker in every slot through which text can reach an exception: each part of the base URL, each argument of a call, and the message of every concrete `httpx.TransportError` class. Next to it, every pathological character found so far: non-ASCII letters and digits, a zero-width joiner, NUL, tab, newline, a space, `%`, `%zz`, `%C3%A9`, `[`, `]`, `@`, `:`, `xn--`, lone surrogates, numbers too long to write, and inputs too long for a URL. ## Proposed approach
Revisable by the executor if it records why.
- Decision: **the adapter makes a single attempt; retries and backoff belong to the caller (F4, `application`)**. Rationale:
  - Every response reaches the caller, and so the store, as soon as it is received, before any wait (ADR 0005, glossary "observation": one per response obtained). If F4 stores after every call, a crash or `Ctrl+C` during a backoff loses nothing.
  - One call is one request is one outcome, which matches F1's one observation per response and lets F4 assign one sequence per response.
  - How many times to retry is policy of a bounded, resumable ingestion execution (attempt budget, audit, resume point), which F4 owns anyway.
  - The decision needs only `domain` types (`SourceStatusError.response.status`, `SourceTransportError`), so `application` never sees `httpx`.
  - F2 still protects the source from a naive caller: after a `429` or a low `Remaining`, the next request waits the cool-down, whatever F4 does.
  - Rejected: an adapter that retries and returns every attempt. It would hold the earlier responses in memory through sleeps, so they are lost on a crash or interruption unless every exit path, `KeyboardInterrupt` included, hands them back. It would need a list-of-attempts result and error type, and F4 would still need its own retry state to resume. Rejected also: letting the library retry (`HTTPTransport(retries=...)`), because those attempts would never reach the store (ADR 0006).
- Decision: **return the response as received in a `domain` value whose attribute names equal the `store` keywords**. Rationale: F4 calls `store(execution_id=..., sequence=..., method=r.method, url=r.url, status=r.status, headers=r.headers, captured_at=r.captured_at, content=r.content)` with no translation, and F1 does not change. Rejected: returning an `httpx.Response` (it leaks `httpx` out of `infrastructure`, ADR 0006), or an `Observation`-like record that holds a hash (hashing is the store's job, RE-1 and RE-2).
- Decision: **every error carries the response it saw, through one attribute on the base class** (`SourceError.response`). Rationale: F4 needs one rule (`except SourceError as error: if error.response is not None: store it`), and "never partial data" holds because no result object exists on any error path. Rejected: a result union with an "ok" flag, because a caller could ignore the flag and use partial data.
- Decision: **stream the body with `iter_raw` and ask for `Accept-Encoding: identity`**. Rationale: `iter_raw` gives the exact received bytes and keeps the bytes already read when the body is cut off (checked above), so a truncated body is still evidence. Asking for identity makes compression unlikely, and if the server compresses anyway, the bytes stay raw and the body fails the JSON check instead of being silently decoded. Rejected: `response.content`, because it applies content decoding and loses the partial bytes on a cut.
- Decision: **build the query string with `urllib.parse.quote(value, safe="")`**, so the request equals the observed URL byte for byte. Rejected: `params=`, which writes spaces as `+` (checked above). Whether the server treats `+` the same way is unknown, so it is not assumed.
- Decision: **no cookie is ever sent** (suggestion: give the client a cookie jar whose policy accepts nothing, such as `http.cookiejar.CookieJar(policy=http.cookiejar.DefaultCookiePolicy(allowed_domains=[]))`, or clear `client.cookies` before each request; confirm in `.venv`). Rationale: requests must not depend on earlier responses in ways the observations never showed; the AC3 test is the requirement.
- Decision: **completeness checks are pure functions of the body bytes and of the requested page or `ocid`** (suggestion). Rationale: F5 or an audit tool can run the same checks again on stored evidence (see § Consumers and migration).
- Decision: **network guard**. The suggested design is an `autouse` pytest fixture, in `tests/unit/test_sercop_source.py` or a new `tests/unit/conftest.py`; either works.
  - The fixture replaces `socket.socket.connect`, `socket.socket.connect_ex`, `socket.create_connection` and `socket.getaddrinfo` through `monkeypatch`. Each replacement records the attempt and raises `OSError`.
  - At teardown, the fixture fails the test if anything was recorded, so a real connection fails the test even if the adapter turned the `OSError` into a `SourceTransportError`.
  - The `no_network` proof test opts out of that teardown assertion, builds `SercopSource(base_url="https://source.invalid/PLATAFORMA")` with no transport, calls it, and asserts that at least one attempt was recorded and that `SourceTransportError` was raised.
  - The reserved `.invalid` domain (RFC 6761) never resolves, which gives a second line of defense.
  - Rejected: an extra package such as `pytest-socket` (no new dependency), or relying on `.invalid` alone (a missing transport would still try DNS).
- Decision: **simulated transport responses** (test-writer note, from the check above):
  - Build mock responses with `httpx.Response(status, headers=[...], stream=httpx.ByteStream(body))`, or with a small `httpx.SyncByteStream` subclass that yields chunks and can raise `httpx.RemoteProtocolError` or `httpx.ReadTimeout` partway.
  - `content=` adds `Content-Length` and is read eagerly, so the adapter's `iter_raw` would raise `StreamConsumed`. Tests that compare exact header lists must not use it.
  - A handler that raises `httpx.ConnectError` or `httpx.ReadTimeout` (with `request=request`) simulates a failure before the status.
  - The handler records every request so a test can assert the URL, the headers, `request.extensions["timeout"]` and the number of requests.
- Decision: **fake clocks**. A fake `monotonic` returns a value the test controls, and a fake `sleep` records each duration and advances that value. The test sets the time between calls by moving the fake clock forward. `now` returns a fixed aware datetime such as `2026-10-10T06:58:00-05:00`. Test values are whole seconds, so the waits compare exactly.
- Revision 2 decisions (suggestions; the tests are the requirement):
  - Decision: **capture each response in an `httpx` response event hook** (`httpx.Client(event_hooks={"response": [...]})`). The client calls the hook right after the transport answers and before its redirect step (`_send_handling_redirects`). The hook reads the body with `iter_raw`, keeps the bytes read so far on an `httpx.HTTPError`, and stores the status, raw headers, bytes and failure on the adapter. It builds no `RawResponse`, because a status outside 100 to 599 would make that raise inside the client. After `send` returns, or raises from its redirect step, the adapter decides the outcome from that capture. Rationale: it stays within `httpx.Client` (ADR 0006), keeps streaming and partial bytes, and makes the `Location` header irrelevant to the outcome. Rejected: catching the redirect-step error after `send`, because the client has already closed the response and the body is lost. Rejected: calling `transport.handle_request` directly, because it bypasses `httpx.Client`, against the wording of ADR 0006, and changes how environment proxies are applied.
  - Decision: **build the request before the pacing wait**, and turn `httpx.InvalidURL` from `build_request` into `ValueError`. Rationale: invalid input never waits (AC10). Rejected: a hand-written length limit, because it would duplicate the library's rule and could drift from it.
  - Decision: **check `base_url` with explicit rules plus `httpx.URL(base_url)`** at construction. The explicit rules cover user information, the empty host and the port, which the library accepts in forms that are wrong for this project. The library parse covers every other form it would reject later. Rejected: the library parse alone, because it accepts `https://:443/...`, user information and out-of-range ports.
  - Decision: **record the end of the attempt in a `finally`** that starts when the request is handed to `send`. The cool-down flag is taken from the captured status and headers, if any.
  - Decision: **a closed flag checked first in each call**, raising `RuntimeError`, the type the library itself uses for a closed client. Rejected: `ValueError`, because the arguments are valid.
- Revision 3 decisions (suggestions; the tests are the requirement; each was tried on a scratch subclass, see § Guidance consulted):
  - Decision: **keep the library from processing `Location`**: in the response hook, after the capture, remove `Location` from the `httpx` response's own headers (`response.headers.pop("location", None)`). `has_redirect_location` is then false and `_send_handling_redirects` returns the response without `_build_redirect_request`, so nothing derived from `Location` runs. The capture already holds the raw headers, so `RawResponse.headers` keeps `Location` as received. The `except httpx.InvalidURL` clause in `_send` and the dropping of a redirect-step `httpx.HTTPError` then become dead code, and the executor may remove them. Rejected: catching `idna.IDNAError` (or `ValueError`) around `send`, because it would also swallow the same error from other places and adds a dependency on the `idna` package's names; catching broadly, which the plan forbids.
  - Decision: **a cookie jar that never stores anything**: `httpx.Client(cookies=<a subclass of http.cookiejar.CookieJar whose extract_cookies does nothing>)`. `httpx` accepts a `CookieJar` and calls its `extract_cookies` after every response, so no `Set-Cookie` is parsed, no warning is issued and the jar stays empty, which also removes the need for `cookies.clear()` before each request. Rejected: a jar whose policy refuses every cookie, because `make_cookies` still parses the headers before the policy runs.
  - Decision: **exact `Remaining` comparison**: after `strip(" \t")` and the ASCII digit check, compare `int(decimal.Decimal(text))` with the threshold (no digit limit; 16,000 digits take about a millisecond), or strip leading zeros and compare lengths first. Rejected: revising AC9 to ignore long values, because it would turn a CPython conversion limit into a pacing rule and weaken the protection of the source.
  - Decision: **strict JSON constants**: `json.loads(text, parse_constant=<a function that raises ValueError>)`, inside the existing `try` that returns no verdict on `ValueError` or `RecursionError`.
  - Decision: **the host checks reuse the library's parse**: read `httpx.URL(base_url).raw_host` and `.host` inside the existing `try` of `_base_url_problem` (catching `ValueError` covers `idna.IDNAError` and `InvalidURL` is caught already), check labels and length on the ASCII text, look for `%` between the brackets for the zone, and build the two shortest request URLs with `httpx.URL`. Return fixed reasons as now, so nothing is chained.
  - Decision: **numeric options with `math.isfinite`** after a type check that rejects `bool` and anything that is not `int` or `float`.
- Revision 4 decisions (suggestions; the tests are the requirement; each was tried in the scratch reference fix, see § Guidance consulted):
  - Decision: **withdraw chaining rather than narrow AC8** (audit F-6). Rationale:
    - The chain was the only remaining path for response content. Narrowing AC8 would hand F4 a rule that is easy to forget: never log, store or format the chain.
    - The change is to drop `from attempt.failure` in two places.
    - The check is structural (I2), so it does not depend on the text that `h11`, `httpcore` or `httpx` write today.
    Rejected: narrowing AC8. Also rejected: wrapping the library exception in a sanitized copy, which would invent a second error type that callers might catch.
  - Decision: **name the failure class in the message** (`f" ({type(failure).__name__})"`; Revision 5: the nearest exported `httpx` class instead, see the Revision 5 decisions). Rationale: it keeps the diagnostic value of the dropped chain, a timeout against a protocol error, without content. Rejected: a new attribute on `SourceTransportError`, which would change `domain` and the pinned constructor.
  - Decision: **check the zone on text that has not been encoded**. For example, after the port check, read the part of `parts.netloc` between `[` and the last `]` and reject it when it holds a `%`.
